# LESSONS — process rules for running this project

One rule per line, with evidence in brackets. Rules marked (P1) are inherited from Part 1 (../project/LESSONS.md) and
keep their Part 1 evidence until this project adds its own.

1. (P1) Check data access (APIs, bot walls, licences) before planning around a source; give every "if obtainable" input a deadline and a recorded fate. [Part 1: DepMap portal bot wall; two inputs lapsed with no recorded decision.]
2. (P1) Lock held-out data before any modelling and commit the lock. [Part 1: split locked day 1 kept all later choices blind.]
3. (P1) A process promise is a check a script enforces, or it is cut. [Part 1: guard/gate scripts let reviewers verify from git alone; prose-only safeguards lapsed.]
4. (P1) Before freezing a decision rule, dry-run it on non-blinded inputs so every verdict branch is reachable. [Part 1: a "fails" verdict proved unreachable.]
5. (P1) Set a control's expected bound by simulating it under the null before the run. [Part 1: permutation controls missed their bands.]
6. (P1) Parallel tracks get their own files and ID ranges. [Part 1: registry corruption and renumbered decisions.]
7. (P1) Ask reviewer subagents to return their report as text as well as writing it. [Part 1: reviewer file writes were refused.]
